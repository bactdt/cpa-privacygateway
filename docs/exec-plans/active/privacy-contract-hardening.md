## 2. 优先任务与验收

| 顺序 | 任务/责任 | 产出 | 验收与依赖 |
|---|---|---|---|
| 1 | 开发者：容量错误原子传播（031） | Mapping→visitor→plugin 明确错误通道 | 多节点/同节点超限，fail_closed=true 绝不放行残留隐私；false 行为明确 |
| 2 | 开发者：准入与格式契约（034） | 缺 ID、空格式、重复 ID/重试的处理 | 相同 ID 不重复计数；正文变更不得以已存在状态绕过扫描；先与宿主核对重试 ID |
| 3 | 开发者：字段覆盖（036、017） | 协议路径和裸字符串数组遍历 | 不改图片/结构字段；工具参数策略有准确正反例；MaxFindings 限制不产生漏扫放行 |
| 4 | 开发者：PII 已知缺陷（028、029） | 身份证/银行卡候选修复 | 校验位 X/x 与银行卡前导字符正例；无效校验和反例不误报 |
| 5 | 开发者：流式帧与刷新（032） | 解析/编码边界、终止输出协议 | 单字节切分、独立 SSE 事件、引号/换行/代理对、终止残缺占位符；先明确宿主 flush 渠道 |
| 6 | 开发者：生命周期与并发（033） | 在途实例保留/准入策略、锁或串行契约 | 满表/TTL/重配不丢活跃映射；同 ID 钩子不能并发修改无锁对象 |
| 7 | 开发者：日志与 ABI 边界（018） | 固定错误分类、版本与内存责任 | YAML 错误不含原值；宿主回调/关闭/缓冲释放验证 |
| 8 | 用户安排后集中验证 | 报告与平台状态 | make check、相关 race/fuzz、C 加载 harness、真实宿主分别记录结果 |

每项同时更新相关设计和台账，不把目标写成现状。当前只有 1–2 的错误安全性列为新增 P0，其他事项按 P1 顺序落地。

## 3. 决策与实现节奏

本轮已确认：完善 docs，不改业务代码、不运行功能测试、不启动子 Agent；保留现有 Go 架构。Header/Query/表单不属于当前修复范围。配置 disabled/priority 的责任、宿主同 ID 并发、流结束可输出机制仍需从宿主约定确认，不能靠字段猜测。

现有护栏测试可用于约束行为；集中测试暂停期间不做广泛重构。修复改变失败行为时明确登记 bug 修复和目标，恢复验证后先完整实现本次范围，再集中执行检查和相关复验。

## 4. 安全与验证矩阵

| 层级 | 数据与工具 | 验证上限 |
|---|---|---|
| 文档 | 链接/索引/必填节检查、源码阅读 | 描述一致性，不代表功能通过 |
| 领域 | 合成值、边界用例、可控分块/fuzz | 检测/往返/错误传播，不代表宿主顺序 |
| Go 编排 | 分发、状态、热重载、race | Go 调用生命周期，不覆盖 C 指针 |
| C ABI | 合成调用、malloc/free、握手/关闭 | 动态库与回调正确性，不覆盖上游协议 |
| 真实 CPA | 拦截合成正文、可控上游/SSE | 真实发送/恢复；避免记录原始隐私或获取站源图片 |
| 平台 | Linux/Windows/macOS 共享库各自验证 | 未验证平台不标可用；Flutter 手机优先级不等于插件已支持 Android |

默认每组测试应有明确时长预算、退出码、环境/版本和结果；timeout 或缺环境应单独标注，禁止以跳过等同通过。
