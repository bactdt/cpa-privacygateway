# 核心信念（智能体优先的操作原则）

> 争议的裁决依据。当"该不该这么做"出现分歧时，回到这份文件，而不是回到聊天记录。
> 参考：OpenAI《Harness engineering: leveraging Codex in an agent-first world》（2026-02-11）。

## 一、通用原则

1. 人类掌舵，智能体执行。人类不直接贡献代码行。
2. 工程师的工作是设计环境、明确意图、构建反馈回路。
3. 上下文是稀缺资源；给地图，不给说明书。
4. 智能体在运行时看不到的东西，对它来说不存在。
5. 强制不变量，不微观管理实现。
6. 中央强制边界，本地允许自主表达。
7. 纠错成本低，等待成本高。
8. 技术债是高息贷款，小额高频偿还。
9. 遇到卡点先问："缺的是什么能力？如何让它既清晰可读又可强制执行？"
10. 人类品味要持续被捕捉——写进文档，或直接编码进工具。
11. 交互式决策必须落盘：确认过但不写进仓库的决策等于没做。
12. 改造存量项目时，重构不改变业务行为；行为变更必须显式登记并单独提交。

## 二、本项目的领域信念

13. **脱敏正确性即安全属性**：检测漏报等于隐私泄露，还原错误等于破坏用户请求。因此 `redact` 领域层必须保持纯净、可穷举测试。
14. **可逆往返优先**：任何脱敏都必须能被同一请求的映射精确还原；占位符 nonce 每请求随机，防止跨请求碰撞与猜测。
15. **失败默认关闭（fail_closed）**：解析失败、超限、格式不支持时默认拒绝而非放行——放行意味着敏感数据可能泄漏到上游。
16. **边界处解析数据形状**：进入领域层的输入必须是明确类型，禁止 YOLO 式探字段。
17. **领域层零宿主依赖**：`redact` 不导入宿主 SDK，宿主相关逻辑一律留在 `main` 包，通过参数传入。

## 三、红线（来自规则 §9）

| 编号 | 红线 |
|---|---|
| R1 | 保留原有业务行为 |
| R2 | 行为变更显式登记并单独提交 |
| R3 | 先护栏后动手：无测试/门禁保护的模块先补保护再重构 |
| R4 | 不做范围外优化，新问题登记台账 |
| R5 | 不删无法判断的内容，标"待核实"并开 issue |
| R6 | 不引入不可内化的依赖 |
| R7 | 不藏信息，关键决策必须落进仓库 |
| R8 | 每一步可回滚 |
| R9 | 追踪日志只含掩码预览：`Finding.Preview` 经 `MaskPreview` 在 `redact` 内生成，原值不出领域层；追踪仅内存、有界，不写磁盘、不写宿主日志 |

## 四、反模式（本项目高发项）

| 反模式 | 对策 |
|---|---|
| 无测试保护就重构 `redact` | R3：先补测试护栏 |
| 重构与行为变更混提交 | R2：严格分离 |
| 关键决策留在对话里 | R7：写进 `docs/` |
| 领域层引入宿主依赖 | 结构测试 `TestDomainLayerHasNoHostSDK` 拦截 |
| 非结构化日志 | 自定义 linter T2 拦截 |
